# tickbudget — дизайн (v1)

Дата: 2026-10-06. Статус: на ревью. Основание: `docs/research/2026-10-06-market-and-pain-points.md`.

## 1. Назначение и границы

**tickbudget** — плагин-зависимость для Paper/Folia с тонким API. Разработчики плагинов
выполняют работу порциями в рамках бюджета мс на тик; админы видят, кто сколько бюджета
тратит. Продукт и для разработчиков, и для админов.

**Успех:** плагины подключают tickbudget вместо самописных планировщиков; админ по
`/tickbudget status` видит измеренное потребление каждого плагина.

**Вне рамок (осознанно):**
- вмешательство в ИИ мобов, удаление сущностей, «оптимизация» чужих задач;
- обещания «+N% TPS» — измеряется только собственная работа;
- телеметрия, сеть, обфускация;
- поддержка Spigot/Bukkit без Paper, версии ниже 1.21, Java ниже 21;
- async-помощники сверх чанков и телепорта.

## 2. Платформа

Paper и Folia, Minecraft 1.21+, Java 21. Purpur/Pufferfish — как форки Paper, без особой
поддержки. Лицензия MIT. Версионирование SemVer; `tickbudget-api` не ломается внутри мажорной версии.

## 3. Модули (Gradle multi-project)

| Модуль | Назначение | Зависит от |
|---|---|---|
| `tickbudget-api` | интерфейсы и record-типы; подключается через `compileOnly` | — |
| `tickbudget-core` | раннер, пул бюджета, учёт, диагностика; знает только `PlatformBridge` | `api` |
| `tickbudget-paper` | `PlatformBridge` для Paper | `core`, Paper API |
| `tickbudget-folia` | `PlatformBridge` для Folia (регионы) | `core`, Folia API |
| `tickbudget-plugin` | `JavaPlugin`, команды, конфиг, выбор моста при старте | все выше |

Правила границ: `api` не знает о `core`; `core` не знает о Paper/Folia; мосты не знают
друг о друге. `core` тестируется без сервера (фейковый мост, управляемые часы).

## 4. Публичный API

```java
TickBudget tb = TickBudget.of(plugin);

tb.run(Target.region(location), BudgetedTask.iterate(items, this::process))
  .budget(Budget.millisPerTick(2))
  .priority(Priority.NORMAL)
  .onComplete(...)
  .onError(...);

tb.chunks().loadAsync(world, x, z);        // CompletableFuture<Chunk>
tb.teleport(entity, location);             // CompletableFuture<Boolean>
tb.schedule(Target.entity(player), () -> ...);
```

- `Target`: `global()`, `region(Location)`, `entity(Entity)`, `async()` — явно задаёт, где
  выполняется работа. Paper: главный поток; Folia: соответствующий планировщик.
- `BudgetedTask`: шаг возвращает `DONE` или `MORE`; раннер не вызывает следующий шаг после
  исчерпания бюджета.
- `TaskHandle`: отмена, статус, прогресс, `CompletableFuture` завершения.
- `Priority`: `LOW`, `NORMAL`, `HIGH`, `CRITICAL`.

## 5. Ядро: бюджет

**Бюджетный домен:** на Paper — один (главный поток); на Folia — регион со своим тиком.
При слиянии/разделении регионов задача переезжает вместе с доменом.

**Расчёт на тик (на домен):**
1. Свободное время = `50 мс − уже потраченное в тике − запас` (запас по умолчанию 5 мс).
2. Делится между плагинами: каждому гарантирован `floor` (по умолчанию 0,5 мс), остаток —
   по весам приоритетов; неиспользованное возвращается в пул.
3. Внутри плагина — по приоритету; вытесненная задача остаётся первой в очереди
   (нет голодания).
4. При отсутствии свободного времени выполняются только `floor` и `CRITICAL`; остальное ждёт.

**Учёт:** `System.nanoTime()` вокруг каждого `step()`. Шаг длиннее выделенного бюджета
фиксируется как нарушение (плагин, задача, длительность).

**Ошибки:** исключение в `step()` не роняет домен — логируется с именем плагина, задача
снимается, вызывается `onError`. При отключении плагина-потребителя все его задачи отменяются.

**Откат на подход A:** если на платформе нет надёжного замера «сколько тика уже
потрачено» (вероятно, Folia), используется только фиксированный лимит задачи без
адаптивного пула. Адаптивный пул включается только там, где замер подтверждён спайком.

## 6. Async-помощники (v1)

- `chunks().loadAsync` — через Paper async-API чанков.
- `teleport` — через `teleportAsync`; вызывается из любого потока.
Другие помощники в v1 не добавляются.

## 7. Диагностика потоков

Режим `debug` (по умолчанию выключен). Вызовы через API tickbudget проверяют контекст
(например, `Target.entity(e)` вызван не из региона сущности). В debug — понятное сообщение
(«вызвано из X, нужно через `tb.schedule(Target.entity(e), ...)`») и стек плагина-виновника.
Без debug — автоматическое перенаправление на правильный планировщик; если невозможно —
исключение с тем же текстом. Граница: диагностируются только вызовы через наш API, не прямые
обращения к Bukkit.

## 8. Админская часть

Права `tickbudget.admin`. Команды:
- `/tickbudget status` — по плагинам: мс за последнюю минуту, задач в очереди, отложено тиков, нарушения;
- `/tickbudget top` — топ плагинов и задач по потреблению;
- `/tickbudget debug on|off`.

`config.yml`: запас, floor, веса приоритетов, лимиты на плагин; безопасные значения по
умолчанию. Статистика — только локальные счётчики в памяти.

## 9. Тестирование

- `core`: модульные тесты (справедливость пула, отсутствие голодания, перегруз,
  исключение в `step()`, отмена при отключении плагина) с фейковым мостом и управляемыми часами.
- Мосты: интеграционные тесты на реальных Paper и Folia (MockBukkit где применимо, иначе
  тестовый сервер в CI).
- Контрактные тесты `api` против случайной поломки совместимости.

## 10. Поставка

Релизы собираются в CI: Modrinth, Hangar, GitHub Releases; `tickbudget-api` — в Maven
(репозиторий выбирается в плане). Имя `tickbudget` на момент 2026-10-06 свободно на Modrinth
и Hangar; перед публикацией перепроверить Spigot, CurseForge, домен, Maven groupId.

## 11. Открытые вопросы (закрыть спайком до реализации адаптивного пула)

1. Надёжный замер потраченного времени тика на Paper (`ServerTickStartEvent`/`ServerTickEndEvent`,
   `getTickTimes`) и на Folia (какие методы Bukkit там не поддержаны).
2. Поведение очередей при слиянии и разделении регионов Folia.
3. Репозиторий публикации API-jar (Maven Central или свой).
4. Точные значения по умолчанию (запас, floor, веса) — подбираются по замерам.
