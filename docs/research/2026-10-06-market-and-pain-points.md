# Исследование: рынок и боли (2026-10-06)

Рабочее название проекта — `tickbudget` (папка/репо), финальное имя выбрано: `tickbudget` (свободно на Modrinth и Hangar на 2026-10-06).
Источники — веб-поиск и документация; часть выжимок получена через сжатие страниц,
поэтому цифры и цитаты отзывов перед публичным использованием надо перепроверить.

## 1. Что уже есть

### Для админов («lag-fixer»)
| Проект | Что делает | Слабое место (по найденному) |
|---|---|---|
| LagFixer (Spigot, ~3500 серверов) | комбайн: сущности, ИИ, чанки | отзывы поляризованы: «сломал ИИ мобов», «concurrency-баги на Folia» |
| LagXpert Free (Modrinth, ~1.4K) | адаптивные лимиты, 4-уровневая state machine, батчи по тикам | сам пишет: нет автотестов, нет дельты «до/после», только скользящие средние |
| LagX, Kinetic (DAB-пейсинг ИИ) | оптимизации сущностей/ИИ | — (страница Kinetic при проверке не открылась) |
| ViewDistanceTweaks | бюджет чанков, замер тика | узкий |
| ClearLag | чистка дропа/мобов | репутация «лагает больше, чем чистит» |
| WETS | размазывает операции WorldEdit по тикам | только WorldEdit |

Вывод: ниша «ещё один оптимизатор для админов» занята и не пользуется доверием.

### Для разработчиков
| Проект | Что делает | Чего НЕ делает |
|---|---|---|
| FoliaLib | кросс-платформенный планировщик (Spigot/Paper/Folia) | заявлена как ранняя, «частые ломающие изменения API», нужна релокация |
| MorePaperLib | автопереключение Bukkit/Folia планировщика, command map, Adventure | **явно не покрывает**: инкрементальную/тик-бюджетную работу, async-операции с чанками, телепорт сущностей |
| PaperLib | async-чанки/телепорт с откатом на Spigot | планировщик, бюджет |

## 2. На что жалуются

**Разработчики (Folia):**
- Флага `folia-supported: true` «совсем недостаточно» (документация Paper) — нужна переработка под регионы.
- Типовые падения: `Bukkit.getScheduler()` (на Folia не поддерживается), доступ к сущностям не из своего региона, `getLivingEntities()` из глобального планировщика, задачи игрока в глобальном регионе, чанк-загрузка не из своего потока.
- Нет внятного руководства «какой код в каком потоке» (PaperMC/Folia#287): потоки команд, событий, ранаблов; поведение при изменении региона.
- Операции «рядом с игроками» через границы регионов — самое сложное в портировании.

**Админы:**
- Лаг от плагинов почти всегда из-за планирования: сканы на каждое событие, чтение БД в главном потоке.
- Скачки MSPT (200+ мс раз в N секунд) хуже, чем стабильно высокое среднее.
- Миграция на Folia упирается в совместимость плагинов (WorldEdit, Citizens, экономика, Dynmap/BlueMap), оценка 2–4 недели отладки.
- Оптимизаторы ломают ваниль (ИИ мобов) и не доказывают эффект.

## 3. Незанятая ниша

Библиотека для разработчиков с тремя вещами, которых нет в FoliaLib/MorePaperLib:

1. **Тик-бюджетный раннер**: «выполняй эту работу порциями, не больше X мс на тик», с учётом региона и приоритетов. Работа ставится на нужный планировщик (регион/сущность/глобальный), бюджет считается по текущему MSPT.
2. **Асинхронные помощники с единым API**: чанк, телепорт, с откатом на Spigot (то, что MorePaperLib оставляет вне рамок).
3. **Диагностика потоков для разработчика**: режим отладки, который говорит «этот код выполнен не в том потоке, вот правильный планировщик», вместо падения.

Плюс тонкая админская часть: `/<cmd> status` — кто из плагинов сколько бюджета использует и сколько работы в очереди. Это лечит «не доказывает эффект», потому что измеряется своя работа, а не обещается «+TPS».

## 4. Чего избегать
- Вмешиваться в ИИ и поведение мобов (главная претензия к комбайнам).
- Обещания «+N% TPS».
- Скрытая телеметрия и обфускация (Modrinth, доверие админов).
- Название «Tickwise»: в `C:\Projects\tickwise-community` уже лежит другой проект.
